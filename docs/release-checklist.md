# Release checklist

- [ ] Confirm final app version and actual implemented behaviour.
- [ ] Complete physical target/device acceptance and record failures, not only successes.
- [ ] Confirm regression results for both RPM methods and unchanged CSV format.
- [ ] Update README, user guide, FAQ, troubleshooting and compatibility.
- [ ] Update all four offline manuals and app strings to match English public documentation.
- [ ] Regenerate and validate versioned PDFs; check both physical paper formats.
- [ ] Capture screenshots from the exact candidate build, in English, without private user data.
- [ ] Run Markdown lint, links, PDF geometry/version, language and public-file checks.
- [ ] Review every staged file and the clean public Git history for private source/data.
- [ ] Obtain owner approval for documentation/target/branding terms and legal privacy details.
- [ ] Verify production signing, AAB, target API and current Google Play requirements.
- [ ] Prepare real release notes, known limitations and actual download/store links.
- [ ] Do not attach APK/AAB to public Releases without a separate owner decision.
- [ ] Confirm Issues, Discussions, private security reporting and Actions settings.

Do not label a development target or untested phone as production validated. Keep a release draft until all mandatory gates are satisfied.
